# UM Link 앱 서비스 정리 (사용자별) — 수정본

> 2026-10-23 개정. 항공서비스학과 자문 결과를 반영해 지상직원 앱을 제외하고,
> 지상 구간 기록 방식과 차별점을 다시 정리했어요.
> **변경된 문단에는 `[개정]` 표시**를 해 뒀어요. 나머지는 원문 그대로예요.

---

## 개요와 전제

UM Link는 비동반 소아(UM)가 출발부터 인계까지 어디서 무엇을 하는지 보호자에게 알리고,
인계 과정을 기록하는 앱 서비스예요.

**[개정]** 이 시스템을 쓰는 사람은 **보호자와 항공사 직원**뿐이에요.
앱은 **2종**(보호자 앱 · 승무원 태블릿 앱)이고, 도착지 지상직원이 쓰는
**인수자 확인 화면 1장**이 더 있어요.
마중 나온 가족은 **시스템 사용자가 아니에요.** 보호자에게 받은 코드를
지상직원에게 보여주기만 해요.

기내 Wi-Fi(대한항공 스타링크)는 보조 수단이에요. 일부 항공편만 제공되고, 이착륙 때
제한되며, 음성·영상통화는 막혀 있어요.

**[개정]** 그래서 **승무원 입력이 기본**이고, 아이 휴대폰은 선택 사항이에요.
지상 구간(체크인·탑승구·도착)은 **지상직원이 새로 입력하지 않아요.**
지상직원은 지금처럼 에스코트와 신분 확인만 하고, 기존에 작성하는 UM 인계 기록을
UM 데스크가 옮겨 적거나 항공사 시스템에서 받아오는 방식으로 채워요.

**[개정] 왜 지상직원 앱을 만들지 않나요**
항공서비스학과 재학생 자문 결과, 현재 지상직의 UM 관련 업무는 **에스코트가 중심**이고,
부서와 소속이 달라 새 직무를 더하기 어렵다고 판단했어요.
UM Link는 기존 서비스를 바꾸는 게 아니라 **기존 서비스에 +@를 얹는 구조**예요.
그래서 현장 업무를 늘리지 않는 범위 안에서 설계했어요.

### [개정] 차별점

AirBand(에어뉴질랜드)는 체크인·탑승·인계·픽업 **네 지점에서 문자**만 보내요.
즉 **비행 중 전 구간이 공백**이에요. 장거리일수록 공백이 길어요.
(시연 기준 노선 ICN→LAX는 비행시간만 650분이에요.)

UM Link가 메우는 건 정확히 그 구간이에요.

| 차별점 | 내용 |
|---|---|
| **비행 중 지속 리포트** | 식사·수면·기분·위치가 지점이 아니라 **계속** 갱신돼요 |
| **기록으로 남는 여정** | 사진·영상이 쌓이고, 도착 후 기념물로 남아요 |
| **인수 코드** | 보호자가 지정한 사람이 맞는지 **보호자가 직접 확인**해요 |

> 인수 코드는 지상직원의 신분 확인을 **대체하지 않아요.** 지상직원은 지금처럼
> 신분증으로 인수자를 확인하고, 거기에 **코드 대조 한 단계**를 더해요.
> 아이를 넘길지 판단하는 주체는 그대로 지상직원이에요.

**[개정]** 와이어프레임: 보호자 앱 **8장**, 승무원 앱 **4장**을 만들어 뒀어요.
(기존 문서의 "보호자 7장·승무원 5장"은 실제 시안 수와 달라 바로잡았어요.)

## 1. 보호자 앱

보호자 앱의 핵심은 진행 현황, 인계 기록, 알림이에요.
아카이브와 AI 콜라주는 부가 기능이에요.

| 서비스 | 내용 | 구분 |
|---|---|---|
| 진행 타임라인 | 체크인, 탑승, 비행 중, 착륙, 인계까지 단계별 현황 | 핵심 |
| 실시간 위치·단계 | 지도보다 "지금 어느 단계인지"를 먼저 보여 줌 | 핵심 |
| 인계 기록 | 누가, 언제, 어디서 인수했는지 기록 | 핵심 |
| **[개정] 인수 코드** | **1회용 코드를 발급해 인수자에게 전달. 사용되면 즉시 알림** | **핵심** |
| 알림 | 위급 알림과 일반 알림을 구분해서 전달 (4번 참고) | 핵심 |
| 아카이브 | 아이 사진·영상을 저장하고 내려받기 | 부가 |
| AI 콜라주 | 기념 사진·영상을 자동으로 만들어 받기 | 부가 |
| 동의 관리 | 촬영, 전송, 보관, AI 처리를 항목별로 동의·철회 | 필수 |

## 2. 승무원 태블릿 앱

객실승무원이 기내에서 쓰는 앱이에요.
상태 입력, 상태 리포트 전송, 사진 촬영, 도착 인계를 한 곳에서 해요.

| 서비스 | 내용 |
|---|---|
| 담당 UM 목록 | 아이별 상태, 새 메시지, 촬영 동의 여부, 지금 할 일 |
| 상태 체크 | 식사, 수면, 기분, 화장실을 버튼으로 입력하고 보호자에게 전송. 특이 상황 보고 포함 |
| 촬영·업로드 | 동의한 아이만 촬영 가능. 연결이 끊기면 저장해 뒀다가 자동 전송 |
| 도착 인계 | 지상직원 사번·QR을 확인해 인계 시간과 인수 직원을 기록 |

> **[개정]** 도착 인계에서 QR을 **스캔하는 쪽은 승무원**이에요. 지상직원은
> 기존에도 들고 다니는 사원증을 보여 주기만 해요. 새 앱이나 새 절차가 없어요.

## 3. [개정] 지상 구간은 어떻게 기록하나요

**지상직원 앱은 만들지 않아요.** 대신 두 가지로 나눠서 채워요.

| 구간 | 기록 주체 | 지상직원이 하는 일 |
|---|---|---|
| 체크인 · 첫 인계 | UM 데스크가 기존 UM 서식 내용을 등록 | 없음 (기존 에스코트) |
| 탑승구 인계 | 승무원이 탑승 확인 시 기록 | 없음 (기존 에스코트) |
| 도착 인계 | **승무원**이 지상직원 사번·QR을 확인해 기록 | 사원증 제시 |
| 최종 인계 | **지상직원**이 인수자의 코드를 확인 | 기존 신분 확인 + 코드 대조 |

### 인수자 확인 화면 (도착지 지상직원용, 1화면)

| 항목 | 내용 |
|---|---|
| 쓰는 사람 | **도착지 지상직원** (예: LAX 도착 서비스) |
| 보이는 정보 | 담당 항공편의 UM 이름·나이·좌석, **보호자가 지정한 인수자 이름** |
| 보이지 않는 정보 | 사진, 상태 기록, 아카이브, 보호자 연락처 — 전부 접근 불가 |
| 할 수 있는 일 | **인수자 확인 하나뿐.** 체크인 등록·탑승 인계는 이 앱에 없어요 |
| 열리는 시점 | 승무원에게 도착 인계를 받은 뒤부터 |
| 코드 유효시간 | 발급 후 3시간, 1회 사용 후 소멸 |

**왜 지상직원이 입력하나**: 아이를 넘겨줄지 판단하는 사람이 지상직원이기 때문이에요.
가족이 자기 인수를 자기가 확인하는 구조는 검증이 되지 않아요.

**업무가 늘지 않는 이유**: 지상직원은 지금도 아이를 넘길 때 인수자 신분을 확인해요.
그건 에스코트 업무의 일부지 새 직무가 아니에요. 더해지는 건 **코드 대조 한 단계**뿐이에요.

**배포**: 전용 앱 설치가 아니라 **1회용 웹 링크**로 엽니다. 위탁 조업사 직원도
기존 기기 브라우저로 바로 쓸 수 있고, 계정 발급이나 설치가 필요 없어요.
아동 정보는 이름·좌석·인수자 이름까지만 보여서 국외이전 범위도 최소예요.

## 4. 알림 우선순위 (보호자 앱만)

알림은 위급과 일반 두 단계로 나눠요. 위급 알림은 끌 수 없고, 일반 알림만 끌 수 있어요.
무음 모드에서도 위급 알림이 울리게 하는 건 기기 설정에 따라 막힐 수 있어요.
"소리와 진동"은 팀의 설계 의도예요.

| 구분 | 예시 | 표시 방식 | 설정 |
|---|---|---|---|
| 위급 | 아이 이상 상황 보고 | 화면 맨 위 빨간 카드, 공항 서비스 연결 버튼 | 끌 수 없음 |
| 위급 | 인계 지연 · **[개정]** 인수 코드 미확인 | 화면 맨 위 빨간 카드, 공항 서비스 연결 버튼 | 끌 수 없음 |
| 일반 | 디지털 인계 완료 | 일반 카드 | 끌 수 있음 |
| 일반 | 기내 상태 리포트 | 일반 카드 | 끌 수 있음 |
| 일반 | 도착 예정 시간 갱신 | 일반 카드 | 끌 수 있음 |
| **[개정] 일반** | **인수 완료** (인수자·확인 직원 이름 포함) | **일반 카드** | **끌 수 있음** |

항공편 지연과 게이트 변경을 위급으로 볼지 일반으로 볼지는 아직 정하지 않았어요.

## 5. 공통 기능 (사용자에게 안 보이는 부분)

- 로그인과 본인인증: 보호자는 만 14세 미만 아동 동의 확인에 필요해요.
- 알림 발송: 푸시와 카카오 알림톡.
- 사진·영상 저장소와 접근 권한 관리.
- 오프라인 저장 후 자동 전송: 승무원 앱 기준이며, 팀의 설계 가정이에요.
- 기록 보관 기간과 삭제 정책.
- **[개정]** 권한 분리: 보호자·승무원·관리자·인수자가 볼 수 있는 데이터를
  앱 코드가 아니라 **DB 권한 정책(RLS)으로 강제**해요. 상태·인계 기록은
  **추가 전용**이라 한번 쌓인 기록은 누구도 고칠 수 없어요.

## 6. 개인정보 · 법 고려사항

만 14세 미만 아이의 사진을 찍고 보호자에게 전송하려면, 보호자(법정대리인)의 동의를
먼저 받아야 해요. 아래는 요약 페이지 기준이고, 국가법령정보센터 원문은 직접 확인하지
못했어요. **제출 전에 원문을 대조해야 해요.**

| 조문 | 내용 |
|---|---|
| 개인정보 보호법 제22조의2 제1항 | 만 14세 미만 아동의 개인정보는 법정대리인에게 동의를 받고, 실제 동의했는지 확인해야 해요. |
| 제22조의2 제2항 | 동의를 받는 데 필요한 최소 정보는 아동에게서 직접 받을 수 있어요. |
| 제22조의2 제3항 | 아동에게는 이해하기 쉬운 양식과 쉬운 언어로 알려야 해요. |

앱에 반영하는 방법:

- 촬영, 보호자 전송, 아카이브 보관, AI 콜라주를 항목별로 따로 동의받아요.
- 동의는 UM 신청 단계에서 보호자 본인인증과 함께 받아요.
- 동의하지 않은 아이는 승무원 앱에서 촬영 버튼이 꺼져요.
- AI 콜라주에서 얼굴 인식은 쓰지 않아요. 얼굴 특징을 추출하는 처리는 생체정보 규정 대상일 수 있어요.
- 다른 승객이 찍히지 않게 안내해요. 초상권 문제가 생길 수 있어요.
- 아이의 실시간 위치는 위치정보법도 확인해야 해요.
- **[개정]** 도착지 지상직원에게는 담당 항공편 UM의 이름·좌석과 인수자 이름까지만 보여요. 사진·상태 기록·보호자 연락처는 접근할 수 없어요.

발표에서는 "법적으로 문제없다"가 아니라 **"동의를 받는 구조로 설계했고, 도입 전 법무
검토가 필요하다"**로 말해요.

출처: 아동의 개인정보 보호 정리(nepla.ai), 개인정보보호위원회 아동·청소년 캠페인,
국가법령정보센터 개인정보 보호법

### [개정] 채팅을 제외한 이유

초기 기획에는 보호자가 승무원에게 메시지를 보내고, 승무원이 읽어서 아이에게
전달하는 채팅이 있었어요. 다음 세 가지 이유로 제외했어요.

1. **승무원 업무 부담.** 승무원 한 명이 UM 여러 명을 맡고, 기내 서비스도 동시에
   해요. 답장 의무가 생기면 "지금 할 일"이 끝없이 늘어나요. 이 위험은 7번 표에
   이미 올라와 있던 항목이에요.
2. **답장이 늦으면 오히려 불안해져요.** 보호자는 메시지를 보낸 뒤 답을 기다려요.
   30분 동안 답이 없으면 "아무 일 없음"이 아니라 "뭔가 있나?"로 읽혀요.
   UM Link가 줄이려던 불안을 새로 만드는 구조예요.
3. **대신할 수단이 이미 있어요.** 상태 리포트(식사·수면·기분)와 위급 알림이
   "지금 아이가 어떤지"를 보호자가 묻지 않아도 먼저 알려 줘요.
   필요하면 위급 알림의 **공항 서비스 연결** 버튼으로 사람에게 바로 닿아요.

> 대신 넣은 것: 승무원이 **보낸 쪽만** 쓰는 상태 리포트. 보호자는 받기만 하고,
> 승무원에게는 답장 의무가 없어요. 단방향이라 업무가 늘지 않아요.
